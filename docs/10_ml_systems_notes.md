# ML Systems Notes

This project is organized as a small research system rather than a single
notebook.

## ML Terminology

**Supervised learning** means each training example has an input and a correct
answer. In this project, the input is recent Treasury yield history, and the
answer is the future change in yields.

**Features** are the numbers given to the model. For each maturity, the project
uses yield levels and recent trailing changes.

**Target labels** are what the model is asked to predict. Here, the label is a
vector of future yield changes for all seven maturities.

**Lookback window** is how much history one example sees. A 60-trading-day
lookback means each input contains the previous 60 trading rows ending at the
forecast origin date.

**Forecast horizon** is how far into the future the target looks. A horizon of
1 predicts the next trading day. A horizon of 5 predicts the change five
trading rows ahead.

**Batch-first tensor** means the first tensor dimension counts independent
examples. The multi-frequency input tensor is shaped `(examples, 60, 28)`, and
the target tensor is shaped `(examples, 7)`.

**Normalization** rescales features so they are easier for a model to use. This
project uses standardization: subtract the mean and divide by the standard
deviation. The mean and scale are fitted using training data only.

**MAE** means mean absolute error. It measures the average size of the forecast
miss, ignoring whether the model was too high or too low.

**RMSE** means root mean squared error. It penalizes large misses more heavily
than MAE.

**Leakage** happens when information from the future accidentally enters the
model inputs or preprocessing. Leakage can make results look better than they
really are.

**Chronological split** keeps time order intact: oldest examples for training,
the next block for validation, and the newest block for testing.

## Separation of Concerns

- data loading lives in `src/market_resonance/data`
- feature windows live in `src/market_resonance/features`
- models live in `src/market_resonance/models`
- training lives in `src/market_resonance/training`
- evaluation lives in `src/market_resonance/evaluation`
- inference lives in `src/market_resonance/inference`
- notebooks explain and inspect results

## Leakage Controls

The most important system rule is that training, validation, test, and inference
responsibilities stay separate:

- train-only normalization
- chronological splits
- validation residuals for uncertainty
- test results reserved for evaluation
- inference runs without labels, loss, gradients, or optimizer steps
